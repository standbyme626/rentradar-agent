# 租房雷达 RentRadar · 项目书

版本：v1.0
日期：2026-10-28
状态：立项
目标城市：深圳（可配置，示例区域：龙岗横岗「居里十舍」）

## 1. 项目概述

### 1.1 一句话

用「持续监控 + 规则/AI 判定 + 证据化展示」替代人肉刷房源，服务两周内的租房决策，并可扩展为多城市租房情报系统。

### 1.2 背景与问题

租房决策的信息是分散的：

- 房源在链家/贝壳/58/安居客/豆瓣/闲鱼/小红书之间重复、真假混杂；
- 价格、上架时间、降价、下架（已租）没有统一视图；
- 通勤时间、拥堵、地铁拥挤、外卖可达性无法从房源页直接判断；
- 隔音、漏水、水压、电、网络等「硬伤」只存在于住户讨论和现场；
- 口碑信息散落在小红书、豆瓣、微博、知乎、本地论坛、12345；
- 人肉刷房源每天 1-2 小时，仍然会漏掉刚上架的好房。

### 1.3 目标

1. 新房源在一个轮询周期内发现并推送；
2. 用可解释的评分筛掉 80% 不合适的房源；
3. 把通勤、外卖、口碑、硬伤变成可比较的维度；
4. 积累价格与存活历史，形成个人数据资产；
5. 架构支持多城市、多源、Web 管理台与公网只读看板。

### 1.4 定位

- 近期：个人自用工具，服务本次租房；
- 中期：可分享给朋友的城市租房雷达；
- 长期：可产品化的租房情报服务（需重新评估合规与数据授权）。

### 1.5 成功标准

| 指标 | 目标 |
|---|---|
| 新房源发现延迟 | ≤ 1 个轮询周期（快循环 10 分钟） |
| 重复推送 | 0 |
| 误判「已下架」 | < 1% |
| 实际联系房源 | ≥ 3 套来自推送 |
| 数据积累 | 7 天价格/存活数据 |
| 判断可解释 | 每个分数有理由，估算项明确标注 |

## 2. 用户与场景

### 2.1 主用户

正在深圳租房、两周内要定房的个人用户。关注预算、通勤、居住质量、生活便利、外卖与口碑。

### 2.2 核心场景

1. 早上收到飞书：「3 套新房源 + 1 套降价」，点开直接看评分理由和原文链接；
2. 下班前筛出 5 套候选，系统给出通勤 p50/p90、地铁拥挤估算、外卖实测；
3. 周末看房，用清单逐项检查隔音/漏水/电/网络，拍照回填；
4. 看中的房源进入「已联系/已看/已淘汰」台账，避免重复沟通；
5. 一周后回看：哪些小区降价多、哪些房源存活短（抢手）。

### 2.3 次要用户

- 朋友/家人：只读分享链接；
- 未来 B 端：公寓运营、中介、企业 relocation 服务（需另行设计权限与合规）。

### 3.2 非目标

- 不做实时地铁站台人数（无开放数据，不承诺）；
- 不做全量美团/饿了么自动爬取（无开放接口，ToS 风险）；
- 不做房源图片/描述的公开转载；
- 不做代看房、代签、交易撮合；
- 不做全国全量覆盖（按城市逐步扩展）。

## 4. 产品方案

### 4.1 功能地图

```
发现
 ├─ 链家 / 贝壳 / 自如 / 58 / 安居客
 ├─ 豆瓣 / 闲鱼 / 小红书（个人房源与口碑）
 └─ 快循环 / 慢循环 / 手动刷新

判断
 ├─ 硬过滤
 ├─ 100 分评分（性价比/通勤/条件/便利/口碑/新鲜度）
 ├─ 假房源识别
 ├─ 通勤与拥堵（采样）
 ├─ 地铁拥挤（估算 + 限流）
 ├─ 生活便利与外卖（POI + 探针）
 └─ 口碑与硬伤（社媒 + 12345 + 现场）

行动
 ├─ 飞书即时 / 日报 / 周报
 ├─ 收藏 / 联系 / 看房 / 淘汰台账
 ├─ 看房清单与现场记录
 └─ 公网只读分享（脱敏）
```

### 4.2 核心流程

```
调度器入队 → Worker 抓列表 → 解析 → 硬过滤 → 详情补全 → 跨源去重
→ 地理编码/通勤/POI → 口碑查询（按需）→ 评分 → 事件 → 飞书
→ 用户看房 → 清单回填 → 台账更新 → 历史沉淀
```

### 4.3 页面与交互

| 页面 | 内容 |
|---|---|
| 仪表盘 | 今日新增/降价/下架、源健康度、抓取成功率、告警 |
| 房源列表 | 筛选、卡片/表格、排序、地图联动、批量操作 |
| 房源详情 | 图片、价格曲线、评分拆解、通勤明细、口碑证据、看房清单 |
| 地图 | 小区标记、价格热力、通勤筛选、噪音源图层 |
| 任务 | 城市×源×筛选×调度×账号/代理策略，立即运行、日志 |
| 账号 | Cookie 导入、健康、最后使用、封禁状态 |
| 代理 | 池子、健康、TTL、按源分配、成本 |
| 日志 | runs、解析失败、验证码、风控、审计 |
| 设置 | 通知、AI、权重、静默时段、公网看板 |
| 分享页 | 脱敏只读，token 访问，可过期 |

### 4.4 通知

- 即时：新簇评分 ≥ 75 或降价 ≥ 8%，每轮最多 5 条，23:00-08:00 静默；
- 日报 09:00：Top 10 新房源 + Top 5 降价 + 市场统计；
- 周报：城市/区域价格与存活趋势；
- 渠道：飞书优先，预留企微/Telegram/邮件/Webhook；
- 去重：事件级 + 簇级，降价才二次提醒。

## 5. 竞品与差异化

### 5.1 GitHub 现状

- 链家/贝壳项目多为 2016-2024 年的数据采集器或房价可视化大屏，普遍断更；
- 租房监控只有豆瓣/自如的小脚本，无主流平台闭环；
- 招标方向 AI 标书生成已卷，但「监控 + 解读 + 匹配」仍有空位。

### 5.2 差异化

1. **监控闭环**：发现 → 判定 → 通知 → 台账 → 历史，而不是一次性爬虫；
2. **证据化 AI**：口碑/图片/文本判定必须带原文引用和置信度，不输出黑箱结论；
3. **通勤与生活**：p50/p90 通勤、拥堵、地铁拥挤估算、外卖实测；
4. **运营级稳定性**：熔断、去重、失败不误判、冷启动基线；
5. **数据资产**：价格、存活、跨源聚类，越用越准。

## 6. 数据源与合规

| 源 | 内容 | 获取方式 | 登录 | 阶段 |
|---|---|---|---|---|
| 链家 | 租房列表/详情 | HTML + Playwright | 列表免登录，详情需登录 | P0/P1 |
| 贝壳 | 租房列表/详情 | HTML + Playwright | 同上 | P0/P1 |
| 自如 | 合租/整租 | Playwright | 部分 | P1 |
| 58/安居客 | 个人房源 | Playwright | 部分 | P2 |
| 豆瓣 | 租房小组/体验 | HTML/API | 部分 | P1 |
| 闲鱼 | 个人房源 | Playwright | 是 | P2 |
| 小红书 | 踩坑/口碑 | Playwright/技能 | 是 | P2 |
| 12345/留言板 | 投诉/硬伤 | HTML/PDF | 否 | P1 |
| 高德/百度 | 地理编码/路径/POI/路况 | 开放 API | Key | P0 |
| 美团/饿了么 | 外卖 ETA/运费 | iPhone 真机探针 | 是 | P0 试验 |

### 6.1 合规红线

- 遵守 robots/ToS，低频请求，不并发轰炸；
- 不转售原始房源、图片、用户内容；
- 不采集/公开房东、经纪人、住户联系方式；
- 公网只发布自己生成的聚合字段与回源链接；
- 口碑结论必须标注「网友讨论，未经核实」并附原文；
- 商业化前评估《个人信息保护法》《著作权法》与平台授权。

## 7. 技术架构

### 7.1 形态

模块化单体，不上微服务：

```
Nginx (TLS/auth/rate limit)
 ├─ FastAPI API + Vue3 SPA
 ├─ 公网只读看板（脱敏）
 └─ WebSocket

Postgres
 ├─ 业务数据 + 任务队列（SKIP LOCKED）
 ├─ Scheduler（只入队）
 ├─ Worker × N（httpx / Playwright）
 ├─ Notifier（飞书）
 └─ Reporter（日报/周报/快照）
```

### 7.2 技术栈

| 层 | 选型 |
|---|---|
| 后端 | Python 3.12、FastAPI、SQLAlchemy 2、Alembic、Pydantic v2 |
| 数据库 | PostgreSQL 16 |
| 采集 | httpx + selectolax；登录源 Playwright |
| 调度 | APScheduler + Postgres jobs 表 |
| 前端 | Vue 3、TypeScript、Vite、Pinia、Tailwind、shadcn-vue、ECharts |
| 地图 | 高德 Web 服务 API + JS API 2.0；百度兜底 |
| AI | 魔搭 Qwen-VL（免费额度）+ 本地 LFM 兜底 |
| 通知 | 飞书 webhook / 应用 bot |
| 部署 | Docker Compose、Nginx、Uptime Kuma、飞牛 NAS 备份 |

### 7.3 关键设计

- 两档轮询：快循环 10 分钟抓最新上架，慢循环 2-6 小时全量；
- 冷启动基线：首次运行只入库不推送；
- 失败不误判：只有成功运行且连续 2 次未出现才标下架；
- 账号/代理池：加密存储、健康检查、冷却、熔断；
- 所有外部结果缓存：地理编码永久、通勤 7 天、POI 30 天、口碑 30 天；
- 评分可解释：每个维度输出理由，估算项明确标注。

## 9. 评分体系

### 9.1 硬过滤

预算、面积、户型、区域、排除词、必须项（电梯/独卫/养宠）。不满足直接丢弃。

### 9.2 总分 100

| 维度 | 权重 | 规则 |
|---|---|---|
| 性价比 | 35 | 同小区/同户型 30 天中位价；低 20% 满分，高 20% 零分 |
| 通勤 | 25 | p50 ≤30min 满分，30-60 线性，>60 零分；p90 稳定性扣分 |
| 居住条件 | 15 | 电梯、朝向、楼层、面积、装修标签 |
| 生活便利 | 10 | 餐饮密度、品类、夜宵、便利店/菜场 |
| 口碑 | 10 | 时间衰减 + 来源多样性 + 置信度；低置信不扣分 |
| 新鲜度 | 5 | 6h 内满分，24h 内 60%，72h 内 30% |
| 风险 | -30 | 假房源、噪音源、取餐不便、严重硬伤 |

### 9.3 解释性

每个分数存 `score_reasons`：

```json
{
  "price": "比同小区中位价低 12%",
  "commute": "公交 32 分钟（p90 45 分钟）",
  "reputation": "近 12 个月 9 条隔音讨论，中等置信",
  "risk": ["距主干道 120 米", "骑手不能进小区"]
}
```

## 10. 里程碑

| 阶段 | 时间 | 交付 |
|---|---|---|
| P0 | 第 1-2 周 | 链家/贝壳列表、评分、快照、飞书、通勤、POI、看房清单、外卖探针试验 |
| P1 | 第 3-6 周 | 详情登录、账号/代理池、多城市、假房源、口碑、地图 UI、Web 管理台 |

## 12. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 平台改版/风控 | 采集失败 | 解析 fixture、页面校验、失败熔断、告警 |
| 账号封禁 | 详情不可用 | 小号、低频、账号池、冷却；不依赖单号 |
| 公网版权/名誉权 | 法律风险 | 脱敏、只放聚合字段、附原文与免责声明 |
| 小区实体对齐错误 | 口碑错配 | 别名表 + 区/坐标校验 + `uncertain` 不参与评分 |
| 样本偏差 | 结论失真 | 多时段采样、置信度、标注估算 |
| 外卖自动化不稳定 | 数据缺失 | 真机探针只做 Top 候选，失败不影响主流程 |
| 过度设计 | 交付延期 | 模块化单体、P0 优先、功能开关 |

## 13. 验收标准

1. P0 端到端跑通 7 天，无重复推送、无明显误下架；
2. 每个房源可查看分数理由、通勤、POI、原始链接；
3. 飞书即时与日报正常，静默时段生效；
4. 看房清单可回填并导出；
5. 外卖探针至少产出 20 条有效样本；
6. P1 验收：Web 管理台可登录、任务可配置、账号失效能告警；
7. P2 验收：公网看板脱敏、可撤销、不可搜索；多城市任务可并行。

## 14. 未来演进

- 多城市复制：城市模板 + 独立限速 + 独立基线；
- 招标方向平移：列表 → 公告解读 → 资质匹配 → 台账，复用同一套监控/通知/证据管线；
- 商业化：订阅制情报服务，需重新评估数据授权、SLA、客服与合规；
- 数据资产：价格/存活/口碑时间序列，可做区域市场报告。
