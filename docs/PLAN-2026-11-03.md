## 0. 一页结论

- 项目已经不是旧项目书里写的“链家/贝壳 HTML 采集 + 房源列表/详情/地图”的经典爬虫产品，而是演进为 **“贝壳 App API + 一句话对话 Agent + Provider 运行时 + 管理控制台”** 的自用租房情报系统。
- 真实设计中最重要的几次转向：数据源从链家 HTML/详情登录转到 **贝壳 App v2 列表 API**；地图从高德转到 **天地图 + 深圳地铁官方 SZMC**；前端从“列表 + 详情页”转到 **对话 + 结果画布 + SSE**；运营从“账号/代理池”转到 **登录/RBAC + Provider 额度/熔断 + 设置/监控运行时**。
- 已经真正做完的是“能采、能评、能聊、能看管理台”：贝壳采集、评分与快照、飞书通知、登录/RBAC/审计、7 个 Provider 的额度与熔断、设置运行时、监控匹配推送、管理端 9/10 页真实接口、LLM 解析 + 回答 + 规则版回退。
- 还没做完的核心不是“再加一个页面”，而是 **数据可信度** 和 **Agent 运行时护栏**：5 号线覆盖约 16%、通勤只有单次采样、价格曲线基本不存在、看房清单/台账没有前端入口、图片/口碑/地图/评测仍是占位或未开始、LLM 还不能自主调用工具。
- 最该先做的顺序：**① 5 号线分片覆盖 → ② 通勤 p50/p90（SZMC，零额度）→ ③ 详情抽屉/价格曲线/评分拆解去假 → ④ 看房清单与台账 UI → ⑤ Agent 工具运行时与护栏 → ⑥ 图片/口碑/地图/评测**。
- 真实剩余工作量：**“自用够用”切片约 12–16 人日（业余 2–3 周）；P0+P1 完整闭环约 50–65 人日（业余 2–3 个月）**；多源/多城市/公网另计。不要再按旧项目书的“6–8 周全量”承诺。

## 2. 真实设计基线

### 2.1 产品形态

**用户端（/）**：一句话说需求 → 对话 + 结果画布。
- 输入预算、通勤、户型、区域、电梯等条件；SSE 推送 `conditions / plan / budget / cards / message / tab / ai / toast / done / error`。
- 结果卡带评分、理由、价格、小区、封面、通勤；可对比、追问、保存监控。
- 真实能力：LLM 解析意图 + 生成回答，失败回退规则版；查询仍是本地确定性逻辑，不是 LLM 自由调工具。

**管理端（/admin）**：10 页控制台——总览、候选工作台、通勤与预算、数据质量、API 管理、Agent 监控、图片/AI、采集任务、运行日志、设置。
- 9 页读真实 `/api/admin/*`；图片/AI 是明确占位；地图用 mock；Agent 评测/成本是设计预览。
- 登录页 `/login`，JWT Cookie + refresh；admin/viewer；审计日志。

**后台**：FastAPI + Postgres + Alembic；systemd `rentradar-api / worker / scheduler`；scheduler 只入队，worker 消费 jobs，Postgres `SKIP LOCKED`；飞书 bot 推送；iPhone 11 Pro 做外卖探针（半自动）。

### 2.2 技术架构（真实）

| 层 | 组件 | 职责 |
|---|---|---|
| 前端 | 浏览器（Vue 3 SPA） | REST + SSE；用户端 `/`、管理端 `/admin`、登录 `/login` |
| API | FastAPI（8010，LAN only） | `/api/agent/*`（SSE、sessions、monitors）、`/api/admin/*`（BFF、providers、jobs、settings、audit）、`/api/listings/*`（详情、watchlist、inspection）、`/api/auth/*` |
| 数据库 | Postgres 16（5433，容器） | listings / snapshots / events / communities / tasks / jobs / runs；users / auth_sessions / audit_log / app_settings；agent_sessions / agent_monitors / agent_monitor_matches；provider_settings / provider_usage / provider_health / provider_calls；commute_samples / poi_cache / delivery_probes / watchlist / inspections |
| 调度 | scheduler（60s tick） | 入队 crawl / analysis / geocode / sampling / digest / monitor_match |
| Worker | worker | 贝壳 App API（主）/ CDP（兜底）；天地图 geocode/POI；SZMC MinTimeJson；ModelScope LLM（解析 + 回答），失败回退规则版 |
| 通知/探针 | 飞书 bot；iPhone 11 Pro | 即时/日报/监控推送；外卖半自动采样 |
| 部署 | systemd + Docker Compose | `rentradar-api / worker / scheduler`；Postgres 容器；LAN only |

### 2.3 Provider 分工（真实，7 个）

| Provider | 域 | 状态 | 用途 / 额度 |
|---|---|---|---|
| `beike_api` | housing | 主通道 | 贝壳 App v2 列表；按日计数不封顶 |
| `beike_cdp` | housing | 兜底 | 受控 Windows Chrome 9333；验证码即停 |
| `tianditu` | maps | 主通道 | 正向地理编码 + POI；约 1 万/日；固定走 10943 出口 |
| `szmc` | transit | 主通道 | 深圳地铁官方 `MinTimeJson` + 站点字典；零额度；仅 3km 内有地铁站的小区 |
| `amap` | maps | 已停用 | 旧地理编码/通勤；额度约 900/5000 预置，不再调用 |
| `didi_mcp` | maps | 已停用 | 沙箱路线会污染通勤，不参与业务 |
| `modelscope_deepseek` | ai | 已配置 | DeepSeek V4.1 Flash；约 500 次/日/模型，Agent 每轮约 2 次 |

关键设计：所有外部调用应走 `provider_runtime`，写 `provider_usage` / `provider_calls`，读 `provider_settings` 的 enable/priority；连续 3 次失败熔断 5 分钟；额度不足调用前拦截。

## 4. 重新基线的需求

> 不再按旧项目书的 21 项 P0/P1/P2 逐条验收；按“真实系统闭环”拆成 9 个工作流。
> 优先级：**P0 = 直接影响这次找房决策；P1 = 让判断可信/可解释；P2 = 平台化/扩展。**

### W1 数据采集与覆盖（P0）

**目标**：5 号线从约 16% 提到可验收覆盖；采集稳定、可解释、不误标。

- 按 5 号线站点 / 商圈拆分 `condition`（`li110460696s<站点id>`、`c<resblock_id>`），多轮抓取合并，保持 `feed_query_id` 和 `house_code` 去重。
- 快循环 10 分钟 / 1 页；慢循环 180–360 分钟 / 6–30 页；任务配置化，不写死。
- 覆盖看板：scope total / 已抓 / 去重后 / 缺页原因；API 未抓全时继续跳过 `suspect`。
- 只在完整覆盖时做 `suspect`，永远不自动 `gone`。

**验收**：单轮去重后 ≥2,500 套；5 号线覆盖 ≥60%（以 scope 分母为准）；连续 7 天 0 重复推送、误标 <1%；每轮有覆盖报告。

### W2 通勤与位置智能（P0）

**目标**：把“单次地铁+步行”升级为可比较的 p50/p90，并修正方向。

- 明确通勤方向：**小区 → 公司**（当前起点是深圳会展中心，需确认公司地址；不要继续用反方向样本）。
- 工作日 4 时段（7:30 / 8:00 / 8:30 / 9:00）采样，落 `depart_bucket`；SZMC 零额度；只对 Top 候选/候选小区跑，禁止全量。
- 聚合 p50/p90、换乘次数、步行距离；接入评分与 UI；旧 AMAP 样本按 1 天阈值逐步重采。
- 小区 3km 内无地铁站时明确“无地铁样本”，不回落高德；UI 标“估算/样本不足”。

**验收**：Top 200 小区有 ≥3 个时段样本；评分使用 p50 而非单次；p90 在详情可见；不新增高德调用。

### W3 价格、存活与台账（P0）

**目标**：让“性价比/降价/抢手”有真实历史；让看房行动可记录。

- 每次成功采集写价格快照；每日至少 1 个快照点；补详情页价格曲线（复用 `/api/listings/{id}` 的 snapshots）。
- 看房清单/台账 UI：收藏 → 联系 → 看房 → 淘汰；检查项（隔音/漏水/电/网络/外卖/物业/电梯）；照片/备注/导出。
- 黑名单/排除词（公寓、床位、中介盘）与“已看/已淘汰”状态打通。

**验收**：Top 100 房源有 ≥2 个价格点（7 天后）；清单可打勾/拍照/导出；台账状态可流转；详情抽屉不再显示假 sparkline/假评分条。

### W4 对话 Agent 与护栏（P1，产品化核心）

**目标**：从“LLM 解析 + 本地查询 + LLM 回答”升级为“LLM 可在白名单内选工具”，但绝不失控。

- 工具注册表：`search_listings` / `get_listing` / `compare_listings` / `commute_lookup` / `price_history` / `save_monitor`；JSON Schema + 参数校验。
- LLM function calling 或严格 JSON 计划 → 执行器；最大步数、超时、重试、取消。
- 护栏：token/调用预算硬停、PII 脱敏、prompt injection 过滤、只读工具、禁止下单/外部写操作。
- 评测：50–100 条黄金 query；意图/工具/接地/延迟；管理端评测/成本页接真实数据。
- **前提**：先做 1 天 ModelScope tool_calls spike，确认稳定性；不稳定就退回“严格 JSON 计划 + 执行器”，不要硬上。

**验收**：工具调用成功率 ≥95%；0 预算超限；trace 可回放；评测集可回归；规则版仍可 fallback。

### W5 图片/假房源（P1）

**目标**：用最小成本补“照片判断”，不追求详情多图。

- 先做 1–2 天数据源调研：贝壳列表只有 1 张封面（可换 `.1280x960`）；详情多图不可用。
- 封面级 MVP：`images` 表、下载/缓存、pHash 复用、Qwen-VL/本地 VL 标签（实拍/样板间、装修、朝向采光、水渍/霉斑、图文不符）。
- 假房源信号：pHash 复用 + 价格异常 + 中介话术 + 图文不符；**≥2 个信号才标记**，不单独定罪。
- 每条标签存置信度 + 证据图；图片页接真实队列，不再用静态设计值。

**验收**：Top 200 候选有封面分析；重复图能命中；假房源标记可解释；不新增付费额度。

### W6 口碑/生活配套（P1）

**目标**：把评分里固定 0.5 的口碑变成“有证据、有置信度”的维度。

- 先做 20 个目标小区的人工验证：豆瓣/本地论坛/12345/小红书/点评，确认命中率。
- 采集：按需查询（只对候选小区），缓存 30 天；不做全城爬。
- 小区实体对齐：名称 + 区 + 坐标 + 别名表；不确定标 `uncertain`，不参与评分。
- LLM 抽取严格 JSON（问题类型/严重度/楼栋/楼层/时间/原文/置信度）；聚合按时间衰减 + 来源多样性 + 提及次数。
- 评分权重 10 分，不高过价格/通勤；通知只在“高风险”时加一行。

**验收**：Top 50 小区有证据链；抽取精度 ≥70%（人工抽样）；口碑分不再是固定 0.5；无证据小区显示“数据不足”。

### W7 地图/前端真实化（P0/P1）

**目标**：去掉 mock，地图和详情只展示真实数据。

- 地图：用真实小区/房源坐标；支持 marker、价格热力、通勤筛选、点击房源卡；坐标系统一 GCJ-02。
- 选型：优先天地图/Leaflet（与现有 Key 一致、不依赖高德）；如用高德 JS，需单独申请 JS Key，不能复用服务端 Key。
- 详情抽屉：真实评分拆解、价格曲线、通勤明细、外卖实测、口碑证据；没有数据就显示“暂无”，不画假曲线。
- 管理端：图片页、Agent 评测/成本页在 W4/W5 完成后接真实数据；任务页补新建/编辑/停用（可选）。

**验收**：地图 marker 全部来自后端；详情无 mock；空状态明确；移动端可用。

### W8 运维/CI/公网（P2）

**目标**：可恢复、可告警、可安全暴露。

- GitHub Actions：ruff + pytest + 前端构建；后端 BFF/SSE/worker 至少加关键集成测试。
- 告警：health、队列积压、源连续失败、磁盘、备份失败；推飞书。
- 备份恢复演练：`deploy/scripts/backup.sh` → 恢复一次；保留 7 天。
- 公网只读看板：token 可撤销、noindex、限流；上公网前 TLS/反向代理/限流；只发聚合字段 + 回源链接，不发图片/联系方式。
- 明确不做：无鉴权公网暴露；把 8010 直接暴露。

**验收**：CI 全绿；告警演练成功；恢复演练成功；分享链接可撤销且不可搜索。

### W9 多源/多城市（P2）

**目标**：在主链路稳定后再扩，不并行。

- 多源：自如、58、安居客、豆瓣、闲鱼、品牌公寓；先做 1 个源 + 跨源去重。
- 多城市：城市配置、域名模板、筛选字典、独立限速/基线；先 1–2 个城市。
- 账号/代理池只在多源/高风控时做；单源不需要。

**验收**：新源可独立开关；跨源同房源不重复；单城失败不影响其他城。

## 6. 验收标准

### 自用主流程（必须）

- 5 号线单轮去重 ≥2,500 套，覆盖 ≥60%（以 scope 分母为准）；连续 7 天 0 重复推送、误标 <1%。
- Top 200 候选有 ≥3 个时段通勤样本，评分使用 p50，p90 可见；不新增高德调用。
- Top 100 房源 7 天后有 ≥2 个价格点；详情抽屉只显示真实数据。
- 看房清单可打勾/拍照/导出；台账可流转；至少实际联系 3 套来自推送。
- 外卖 ≥20 条、覆盖午/晚两个时段；没有样本时明确显示“无数据”。

### Agent/数据可信（P1）

- 工具只调白名单；参数校验；预算硬停；PII/注入护栏；trace 完整可回放。
- 评测集 ≥50 条，意图/工具/接地有基线；管理端评测/成本页不再写死。
- 图片标签有置信度 + 证据；假房源 ≥2 信号；口碑有原文链接 + 置信度。
- 地图 marker 全部真实；无 mock；空状态明确。

### 运维/安全

- CI 全绿；告警/恢复演练通过；备份可恢复。
- 公网只读看板 token 可撤销、noindex、限流；TLS/反代后才可暴露。
- 无凭据入库/入前端；`.env`/`.secrets` 不提交；日志脱敏。

## 7. 风险与不做

| 风险 | 影响 | 应对 |
|---|---|---|
| 贝壳风控/验证码 | 采集中断 | 低频、复用连接、指数退避；CDP 人工过验证；验证即停 |
| 单条件 offset 2999 | 覆盖上不去 | 按站点/商圈/价格带拆片；多轮合并去重；不盲目加页 |
| 详情/多图不可用 | 图片 AI 只能封面 | 先封面级 MVP；不投入详情逆向；接受局限 |
| SZMC 只覆盖 3km 内有地铁站 | 部分小区无通勤 | 明确“无地铁样本”；不回落高德；公交/步行另算 |
| ModelScope 500/日/模型 | Agent 放量受限 | 预算硬停；解析/回答两次调用；缓存意图；规则版兜底 |
| 口碑覆盖低/实体对齐错 | 结论失真 | 先人工验证 20 小区；`uncertain` 不参与评分；只展示证据 |
| 地图 Key/坐标系 | 地图不可用/偏移 | 优先天地图/Leaflet；统一 GCJ-02；JS Key 单独申请 |
| 公网版权/名誉权 | 法律风险 | 只发聚合字段 + 回源链接；不转售图片/描述；公网前评估 |
| 范围蔓延 | 交付延期 | 按 Track A/B 切；每周只做一件 P0；不做多源/多城并行 |

### 明确不做

- 实时地铁站台人数/实时公交到站（无开放数据；抓取有法律风险）。
- 自动抓链家、贝壳详情逆向、账号池/代理池（单源阶段）。
- 自动把 `suspect` 改成 `gone`。
- 全量高德 enrich、恢复滴滴沙箱路线、使用 OpenRouter 收费模型。
- 未加鉴权/TLS 就公网暴露 8010 或管理端。
- 把规则版回答描述成“模型已规划/图片分析已完成”。
